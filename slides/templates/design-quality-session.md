# Design Quality Session — Slide Template

Use this template to structure any Design Quality Session presentation.
Fill in each section with your content before creating the deck in Figma Slides.

---

## Writing guide

### Action titles (McKinsey style)

The slide title is not a topic label — it is the takeaway. The audience should understand your point from the title alone, without reading the body.

| Instead of | Write |
|---|---|
| `Current state of the portfolio` | `Portfolio IA creates confusion at every decision point` |
| `Why this approach?` | `Progressive disclosure reduces cognitive load without hiding depth` |
| `Measuring success` | `We'll know it worked when task completion improves 20%` |
| `What we need to move forward` | `We need squad time allocated to unblock production` |

**Rules:**
- Use a verb or a clear assertion — never a noun phrase alone
- Answer "so what?" not "what is this about?"
- One idea per title, max one line
- Active voice preferred: "We decided X", "X causes Y", "X unblocks Y"

---

### Content structure (Minto Pyramid)

Use the Minto Pyramid to order information on every content slide: lead with the conclusion, then support it. Never bury the point at the end.

```
         ┌─────────────────┐
         │   CONCLUSION    │  ← Action title — the "so what"
         └────────┬────────┘
          ┌───────┴───────┐
          │  KEY POINTS   │  ← 2–4 supporting arguments
          └───────────────┘
     ┌────────────────────────┐
     │   SUPPORTING DETAIL    │  ← Data, examples, evidence (body copy)
     └────────────────────────┘
```

**SCR pattern** — use this to frame any content slide:

| Layer | Question it answers | Example |
|---|---|---|
| **Situation** | What is the context everyone agrees on? | "The portfolio screen is the most visited in the app." |
| **Complication** | What changed or went wrong? | "Users can't find their full asset breakdown." |
| **Resolution** | What is the recommended action? | "We restructure the IA using progressive disclosure." |

The **title carries the Resolution**. The body carries Situation + Complication briefly, then evidence.

**Example — before and after:**

*Before (topic title + bottom-up body):*
> **Title:** Current state analysis
> Body: Users visit the portfolio screen frequently. There are 12 assets visible by default. Research shows confusion in finding full breakdown. We think progressive disclosure could help.

*After (action title + pyramid body):*
> **Title:** Users lose trust when they can't see their full position at a glance
> Body: Portfolio is the #1 visited screen — yet 68% of users exit without finding their full breakdown. The current flat IA forces users to scroll past irrelevant assets to reach the data they need.

## Slide types reference

| Type | When to use |
|---|---|
| Cover | Opening slide — title + date |
| Index | Agenda — list of sections |
| Section divider | Transition between topics — number + title only |
| Content — pillars | 2–3 key concepts side by side |
| Content — statement | One big idea, minimal copy, JTBD |
| Content — numbered steps | Sequential phases or project timelin |
| Content — call to action | Single ask, decision, or blocker |
| Content — exploratory | Open questions, hypothesis, what-if |
| Closing | Thank you + logo |
